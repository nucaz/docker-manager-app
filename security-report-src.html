1. Resumen Ejecutivo

Docker Manager es una aplicación Electron de escritorio para gestión y despliegue de proyectos Docker. La evaluación de seguridad cubre el análisis estático del código fuente (main.js, preload.js, renderer/app.js, renderer/index.html), la revisión de dependencias npm y la configuración de hardening de Electron.


La aplicación demuestra prácticas de seguridad maduras: uso de spawn() con arrays de argumentos, validación estricta de inputs, y todas las opciones de hardening recomendadas por la documentación de Electron. Se identificaron y corrigieron 2 issues menores durante esta auditoría.


Resultado: APTO PARA PRODUCCIÓN tras aplicar las correcciones documentadas en la sección 4.

4.2 Recomendaciones Menores (Sin Riesgo Inmediato)

#SeveridadDescripciónEsfuerzo
REC-01 INFO CSP con 'unsafe-inline' para scripts
La cabecera Content-Security-Policy permite scripts inline (script-src 'self' 'unsafe-inline'). En una aplicación Electron cargando solo archivos locales el riesgo real es muy bajo, pero migrar los inline scripts a archivos externos permitiría eliminar esta excepción.		 Alto
REC-02 INFO Firma de código del instalador no configurada
El campo publish: null y la ausencia de certificados de firma implica que Windows Defender SmartScreen puede mostrar advertencias al instalar. Se recomienda adquirir un certificado EV Code Signing para builds de distribución pública.		 Medio
REC-03 INFO PowerShell con -ExecutionPolicy Bypass
La función psRun() invoca PowerShell con -ExecutionPolicy Bypass para operaciones WSL. Es comportamiento intencional y necesario, pero se documenta para que revisiones futuras no lo marquen como error.		 —

7. Vectores de Amenaza Evaluados

7.1 Inyección de Comandos (Shell Injection)

Estado: MITIGADO

Todos los comandos Docker se ejecutan con spawn(binary, argsArray). Los argumentos nunca pasan por un shell; la interpolación de strings con input del usuario no ocurre en ningún path de ejecución. El regex SHELL_INJECT_RE = /[;&|`$<>(){}!\\]/ previene que caracteres peligrosos lleguen siquiera al proceso.

7.2 Cross-Site Scripting (XSS)

Estado: MITIGADO

La función escHtml() se aplica consistentemente antes de insertar datos externos en el DOM. El contexto del renderer está aislado (contextIsolation: true). Los accesos directos al DOM con innerHTML de datos confiables (templates internos) son la excepción documentada.

7.3 Prototype Pollution / Dependency Confusion

Estado: NO APLICA

Al no tener dependencias de producción de terceros, la superficie de ataque de supply-chain es mínima (limitada a Electron y electron-builder, ambas con 0 CVEs activos).

7.4 Escalada de Privilegios

Estado: MITIGADO

El instalador NSIS usa requestedExecutionLevel: asInvoker. La aplicación no solicita UAC ni privilegios elevados. Las operaciones Docker requieren que el usuario sea miembro del grupo docker-users, lo cual es responsabilidad de Docker Desktop.
